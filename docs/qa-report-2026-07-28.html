Section 01

Blocking defects found and fixed

Three defects would have been visible to any visitor and embarrassing in front of a prospect. All three are resolved on the live site.

Blocker

The About page rendered two navigation bars and two footers

/about-us/

This page was the only one of 22 still on the default theme template, while every other page uses Elementor Canvas. The theme therefore added its own header and footer on top of the ones built into the page. Visitors saw the navigation twice, the footer twice, and two competing H1 headings.

The duplicated theme footer also carried contact details that are no longer correct: info@bigbinarytech.com, 0326 8880101 and an address of “123 Tech Park, Lahore”. A visitor who used those details would not have reached anyone.

Fixed. Page template set to Elementor Canvas, matching the other 21 pages. Verified live: one header, one footer, one H1, and no stale contact details anywhere on the site.
Blocker

A designer’s brief was published as customer-facing copy

/e-books-guides/

Under a heading that read “See What’s Inside Before You Download” and a paragraph promising “a preview of the actual content you’ll receive: real pages, real frameworks”, the page listed five build instructions rather than any preview. The published text included “Page 4 Comparison Matrix (e.g., AWS vs Azure vs GCP feature comparison)” and “Page 5 Real Project Screenshot (e.g., dashboard, workflow, or system interface)”.

Fixed. Rebuilt as a five-card grid describing how every guide is structured. The section no longer promises a preview that does not exist, and no build instructions remain in published copy.
Blocker

An unfinished page was publicly reachable

/pos-systems/

The page was live and read “This page is being prepared. The full POS Systems layout and content are on the way, check back soon.” Nothing on the site linked to it, and POS Systems is not part of the agreed six-service menu.

Fixed. Set to draft and given a permanent redirect to /retail-pos/, which is the page that actually covers this offering.

Section 02

Layout and content defects fixed

These came from the same root cause: when page content was converted into the new design, several labels were flattened into plain paragraphs and landed one position away from the element they belong to.

Major

The “Most Popular” badge sat on the wrong package on five pages

/pricing/ · /careers/ · /digital-transformation/ · /social-media-marketing/ · /enterprise-odoo/

On the pricing page the badge labelled Starter rather than Growth. The same one-card offset appeared in four other package grids, so in each case the cheapest tier was being promoted as the most popular one. The badge was also rendering as ordinary body text rather than as a badge, so it read as a stray line inside the card.

Fixed. Each badge is now a styled pill on the correct middle tier. Verified live on all five pages.
Major

Module numbering was one card out of step

/enterprise-odoo/

In “The Four Pillars of Enterprise Automation”, the label “Module 02” sat above Module 01’s feature list, “Module 03” above Module 02’s, and so on. “Module 01” floated outside the cards entirely.

Fixed. Each label now sits at the head of the card it names.
Major

Every social media icon in the footer led nowhere

All 22 pages

The LinkedIn, X and GitHub icons in the footer were all set to href="#", so clicking any of them did nothing. This was present on every page of the site, and the previous design had the same placeholders.

Fixed. Wired to the profiles that actually exist: linkedin.com/company/big-binary-tech and github.com/bigbinarytech. No X account exists for Big Binary Tech, so that icon now points at the active Instagram account instead.
Major

Prices read back to front

/pricing/

Package prices rendered as two identical grey paragraphs in the wrong order, for example “$2,500” followed by “/mo per specialist · Starting at”. The unit and the qualifier both trailed the number.

Fixed. Restructured so the qualifier sits above the figure as a small label, the figure is set prominently, and the unit reads underneath as a caption.
Major

Three pricing cards shared two buttons

/pricing/

The “Get Started” and “Talk to Sales” links sat outside the card grid rather than inside the cards, so no individual package had its own call to action.

Fixed. Each card now carries its own button, pinned to the foot of the card so all three align regardless of how much content sits above.
Major

A booking link promised a scheduler that does not exist

/contact-us/

The “Book a video call” card invited visitors to “Pick a time”, but the link went nowhere and the site has no scheduling tool connected.

Fixed. The card now says we will send a calendar invite, and the link takes the visitor to the enquiry form, which works.
Major

Contact details were inconsistent across the site

Sitewide

Three different email addresses and two different phone numbers appeared across the site depending on which page a visitor landed on.

Fixed. The site now reports exactly one email address (business@bigbinarytech.com) and one phone number (+1 307‑443‑4365) on every page.
Major

Smaller copy and interface faults

/pricing/ · /about-us/

Three further faults, all now resolved: the question “Not sure which package fits?” appeared with no answer or link following it; the instruction “Swipe to compare all packages” displayed at every screen width including desktop, where nothing scrolls; and one image carried no alternative text for screen readers.

Fixed. The question now leads somewhere useful, the swipe hint appears only below 760 px where the table genuinely scrolls, and the image issue disappeared with the template correction.

Section 03

Also resolved in this release

Fixed earlier in the same work, listed here so the sign-off covers the full scope of what changed.

Fixed

The contact form was discarding every enquiry

/contact-us/

The form was published with no handler behind it. Submitting it reloaded the page and threw the enquiry away without showing an error, so every lead submitted since launch was lost.

Fixed. Contact Form 7 and Flamingo installed. Submissions are now delivered by email and stored in WordPress. Tested end to end on the live page: the enquiry sends, the confirmation appears and the form resets.
Fixed

Privacy Policy and Terms of Service did not exist

Footer, all pages

Both footer links were dead anchors. WordPress still held its default privacy stub in draft, full of “Suggested text:” boilerplate.

Fixed. Both pages written against how the site actually behaves and published, built on the site’s own layout so they match everything else.
Fixed

Page addresses carried numeric suffixes

Six pages

Six pages were published at addresses such as /about-us-2/ and /solutions-3/, which look unfinished in a browser bar or a shared link. The cause was that images in the media library had claimed the clean addresses.

Fixed. All six now use clean addresses, with permanent redirects from the old ones so no existing link breaks, and 331 internal links updated to match.
Fixed

Home page showed work that could not be substantiated

/

The Selected Work section described three projects with no supporting evidence, and the hero presented a revenue figure as if it were a product metric.

Fixed. Replaced with three platforms that genuinely exist, shown with their real product artwork and attributed to the team that built them.

Section 05

Open items owned by Big Binary Tech

None of these block launch. Two are short admin tasks; two are decisions that cannot be made from the code.

Decision needed

Roughly 100 published statistics are unverified

The site publishes claims such as “200+ Industry Specific Projects”, “80+ POS Systems Deployed”, “12M+ Global Users”, “98% Client Retention” and “Rated 4.8/5 by readers”. None can be confirmed from the codebase, though a services business delivers plenty of work that leaves no code behind, so that is not evidence they are wrong.

One point does need attention regardless: the site currently states three different project totals. Pages variously claim 200+, 60+ and 50+ projects delivered, and client satisfaction appears as both 98% and 92%. Anyone reading two service pages will see the contradiction.

A page-by-page checklist of every figure has been prepared for the team to confirm, correct or remove.

Admin task, about 5 minutes

Four pages have no search engine description

/odoo-erp/, /custom-software-development/, /privacy-policy/ and /terms-of-service/ have no meta description, so search engines will invent one from page text. These are stored by the SEO plugin and can only be set from the WordPress admin, not from the site code. Draft text has been prepared.

Admin task, about 10 minutes

Nine page titles are too long for search results

Nine titles run between 63 and 67 characters and will be cut off in Google. Same situation: these are set in the SEO plugin and need an admin login. Shortened versions have been prepared for each.

Admin task, about 2 minutes

Enquiry notifications go to the wrong inbox

The contact form works and every submission is stored, but the notification email is currently addressed to the WordPress administrator account rather than business@bigbinarytech.com. The plugin will not accept this change through the site code and needs it set once in the admin. Until then, submissions are safe and viewable under Flamingo, but the notification lands in the wrong place.
